# Отчёт об уязвимости: SQL-инъекция в DVWA

## 1. Заголовок
SQL-инъекция в параметре `id` на странице `/vulnerabilities/sqli/`

## 2. Краткое описание
В параметре `id` обнаружена уязвимость типа SQL-инъекция. Злоумышленник может выполнить произвольные SQL-запросы к базе данных и получить доступ к конфиденциальной информации (пароли, данные пользователей).

## 3. Тип уязвимости
SQL Injection (SQLi)

## 4. Критичность
High (CVSS 8.1)

## 5. Затронутый компонент
- **URL:** http://localhost:8080/vulnerabilities/sqli/
- **Параметр:** id
- **Метод:** GET

## 6. Шаги воспроизведения
1. Открыть страницу `http://localhost:8080/vulnerabilities/sqli/`.
2. Ввести в поле User ID значение `1`.
3. Убедиться, что отображаются данные пользователя.
4. Ввести payload: `1' OR '1'='1`.
5. Нажать Submit.
6. Наблюдать вывод всех пользователей из базы данных.

## 7. Доказательство
- **Payload:** `1' OR '1'='1`
- **Результат:** выводятся все записи из таблицы `users`.
- **Скриншот:** ![[Снимок экрана 2026-09-22 в 01.18.44.png]]
- **Пример вывода:** admin, Gordon, Pablo

## 8. Влияние (Impact)
- Злоумышленник получает доступ ко всем данным в базе.
- Возможна утечка паролей, email, персональных данных пользователей.
- В некоторых конфигурациях возможно выполнение команд на сервере.

## 9. Рекомендации по устранению
1. Использовать **подготовленные выражения (prepared statements)** с параметризацией запросов.
2. Экранировать специальные символы перед вставкой в SQL-запрос.
3. Ограничить права пользователя базы данных (не использовать `root` для веб-приложения).
4. Включить WAF (Web Application Firewall) для фильтрации подозрительных запросов.
